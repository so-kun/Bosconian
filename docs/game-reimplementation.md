# ネイティブ再実装（route c）

ROMを実行せず、ゲームの挙動を TypeScript で再実装する方針（ユーザー当初のルート）。
著作物であるグラフィック/音声は**実行時にユーザーのROMから読む**（再配布しない）。
ロジックは自作コード。エミュレータ（起動画面まで検証済み）を参照基盤とする。

## 現状（第1段）

`src/game/`:
- `scene.ts` — ゲーム状態とループ。自機の8方向移動、ヘディング、ショット、
  スターフィールドのスクロール連動
- `runner.ts` — requestAnimationFrame ループ＋キーボード入力→canvas描画

再利用している検証済み資産:
- `src/video/starfield.ts` — Namco 05XX スターフィールド（MAMEの解析済みLFSR
  アルゴリズムから再実装、BSD-3参照）。16bit フィボナッチLFSR、ヒット検出
  (mask 0xfa14 / value 0x7800)、2バンク、スクロール
- `src/video/gfx.ts` / `palette.ts` / `render.ts`(drawSprite) — グラフィックデコード、
  パレット、スプライト描画
- 自機スプライト = gfx2 index 0 系（8方向回転）、色1（白）

## 動作

ブラウザで「プレイ（再実装）」モードを選ぶと、星空を飛び回り、ショットを撃てる。
矢印/WASD=移動、Space=ショット。

## 第2段: 敵編隊（実装済み）

`src/game/enemies.ts`:
- I型戦闘機のスカドロン（gfx2 index 24-31、8方向回転）
- 状態機械: entering（隊列へ進入）→ formation（隊列飛行、中心がドリフト）→
  attacking（自機へ突進）→ dispersing（画面外へ離散）
- **リーダー撃破で残存機が離散**（ボスコニアンの特徴的挙動）
- `velToDir` で速度→8方向スプライト
- scene 統合: 定期スポーン、弾×敵の当たり判定（撃破+スコア: リーダー200/雑魚70）、
  敵×自機の当たり判定（ミス→残機減・無敵点滅・中央リスポーン）、HUD（SCORE/SHIPS）

## 第3段: 基地（スパイ艦）（実装済み）

`src/game/base.ts`:
- 6砲台＋中央コアの六角形基地。砲台は個別に破壊可（各200点）
- コアは周期的に開く（"開口"時のみ脆弱）、または**全砲台破壊で露出**。破壊で1500点
- 砲台からプレイヤーへ弾を発射（enemy bullets）
- **描画（実機画面と照合して修正）**: 本物の要塞は「6個の緑の球体ポッド（上部に
  マゼンタのキャップ）＋中央の緑コア（赤いマウスバー）＋接続チューブ」からなる
  フラットトップ六角形の分子状ステーション。これを参照画像に忠実に手描き再構築。
  各ポッド＝6砲台に対応し、撃破されたポッドは消えて残り火になる（個別破壊が視覚化）。
- **訂正**: 以前は gfx2 #52-55 を基地として使っていたが、実機画面と照合した結果
  **#52-55 は基地の「爆発」アニメ**（白い塊＋放射線）であり誤用だった。#56-59 も
  爆発フレーム。無傷の要塞はスプライトではなくタイル/構造描画。
- scene 統合: 常時1-2基を維持、弾×基地の当たり判定、enemy bullets×自機、
  基地本体×自機の接触判定

## グラフィック忠実度の自己チェック（ROM照合）

ユーザー指摘を受けてROMと照合した結果:

| 要素 | 出典 | 忠実度 |
|---|---|---|
| 自機スプライト | 実ROM gfx2 #0-7（8方向回転） | ✅ 本物 |
| 敵I型戦闘機 | 実ROM gfx2 #24-31 | ✅ 本物 |
| 弾（自機/敵） | 実ROM gfx3 ドット（4×4） | ✅ 本物に修正済み |
| フォント（HUD） | 実ROM gfx1 | ✅ 本物 |
| スターフィールド | 05XX LFSR（実チップ解析準拠） | ✅ 本物 |
| パレット | カラーPROM＋抵抗ネットワーク | ✅ 本物 |
| **基地（スパイ艦）** | 実機画面に忠実な手描き再構築（緑ポッド六角形） | ⚠️ 形状は一致。ROMピクセル抽出は将来課題 |

### 基地グラフィックの実データ抽出（解決）

**訂正の経緯**:
1. 当初 gfx2 #52-55 を「基地」としたが、実機スクショと照合し **#52-55 は基地の爆発**と判明。
2. 次に緑ポッドの六角形を手描き再構築したが、これも近似にすぎなかった。

**最終的な解決 — 実ROMデータの抽出**（エミュのデッドロック解決は不要だった）:
- ROMバイト列をポッド系タイルコード帯(0xb8-0xef)で走査 → **sub ROM 0x0160 に配置テーブル**を発見。
- 逆アセンブリで参照元を特定 → **sub 0x03d6 が基地描画ルーチン**。
  4象限×(4行×4列)をタイル面へ、属性を+0x800のアトリビュート面へ書き込む（行ストライド32）。
- **Z80コアでこのルーチンだけを直接実行**（PC=0x03d6、648ステップ）してVRAMをダンプ。
  ゲーム本編の起動もデッドロックの通過も不要。`analysis/_execbase.ts`
- 得られた実データ（タイルコード＋カラー属性）を `src/game/baseGfx.ts` に格納し、
  `base.ts` はそれを実カラーPROM経由で描画する。ハードウェアが描くものと同一。
- 基地タイプは複数存在（0x0160、0x01a0 等、各0x40バイト＝4象限×16）。

**この手法は他の要素にも適用可能**（機雷・アステロイド・爆発など）。

## 第4段: レーダー表示（実装済み）

`scene.ts` drawRadar: 右帯にボスコニアン象徴のレーダースコープ（緑枠）。
自機を中心に周辺ワールドを俯瞰し、自機（白・中央固定）・基地（緑）・敵（青）・
機雷（淡黄）をブリップ表示。ラップ対応（世界の継ぎ目をまたいでも最短オフセットで表示）。

## 第5段: アラート状態＋セクター攻略ループ（実装済み）

`src/game/alert.ts` `AlertSystem`:
- **GREEN → YELLOW → RED** の3段階コンディション状態機械。
  - 発砲（基地が画面内）や基地の発砲で **YELLOW（"ALERT"）** に上昇＝発見された状態。
  - 基地撃破で **RED（"CONDITION RED"）**＝艦隊が緊急出撃（即時スコードロン増援）。
  - 一定時間放置で1段ずつ自動デエスカレーション。
- コンディションに応じて敵の攻撃性（スコードロン出撃頻度）を倍率スケール。
- 画面中央に警告コールアウトを点滅表示（実フォント、状態色）。

`scene.ts` セクターループ:
- 各セクターの基地撃破ノルマ（初期6、クリアごとに+1、最大12）。
- ノルマ達成で **セクター前進**＋ボーナス点＋"SECTOR CLEARED" バナー。
- HUD に `SECTOR n` と `COND GREEN/YELLOW/RED`（状態色）を常時表示。

## 第6段: コスモマイン（機雷）（実装済み）

`src/game/mine.ts` `Mine` / `detonateChain`:
- 実gfx2スプライト #40（放射状スポア星）を点滅描画（緑バンク7）。
- 各セクター開始時にクラスタ状に散布（連鎖が活きる配置）。決定的LCGで再現可能。
- 接触で自機撃墜。射撃で撃破＝**連鎖爆発**（近傍の機雷をBFSで誘爆、各50点）。
- レーダーに機雷ブリップ（淡い黄）を表示。

## 第7段: サウンド（実装済み）

`src/audio/sound.ts` `SoundEngine`（Web Audio 合成＋SpeechSynthesis 音声）:
- 外部音源アセットなし。SEはWeb Audioでプロシージャル合成、音声コールアウトは
  ブラウザの SpeechSynthesis を使用（node/テスト環境では無音で安全に縮退）。
- シーンは音声を持たず、`scene.sfx` に**イベント文字列**をキューイング。
  runner が毎フレーム drain して `SoundEngine.play()` に渡す（シーンはnodeテスト可能）。
- イベント: fire / explosion / baseExplode / mineExplode / playerHit /
  alertYellow / alertRed / sectorClear / blastOff。
- 音声: "Blast off"（開始）, "Alert"（YELLOW）, "Condition red"（RED）,
  "Sector cleared"。ブラウザのオートプレイ制限のためユーザー操作で AudioContext を resume。
- `M` キーでミュート切替。

## 第8段: 大規模ラップワールド＋スクロール（実装済み）

`src/game/world.ts` ＋ `scene.ts`:
- 1024×1024 のトーラス（上下左右ラップ）ワールド。自機はワールド座標を持ち、
  **画面中央に固定**表示、ワールドがその下をスクロール（クラシックなボスコニアン方式）。
- 静的オブジェクト（基地・機雷）とワールド弾（自機弾・敵弾）はワールド座標。
  描画・当たり判定は**最短ラップオフセット**で screen へ変換（継ぎ目対応）。
- 敵スコードロンは画面空間で中央の自機をホーミング（近接攻撃者として簡潔に維持）。
- 基地はワールド各所に散在。**レーダーで探索**して向かう（象徴的なゲームループ）。
- ワールド幾何ヘルパー（wrap/wrapDelta/nearestImage/wrapDist）を単体テスト。

## 第9段: セッション構造（ゲームオーバー／エクステンド／リスタート）（実装済み）

`scene.ts`:
- **残機0でゲームオーバー**。フィールドを凍結し、"GAME OVER" ＋点滅 "PRESS FIRE"
  を中央表示。ファイア押下で `resetGame()` により新規ゲーム開始。
- **エクステンド（1UP）**: 初回15000点、以降50000点ごとにボーナス残機（"EXTRA SHIP"
  バナー＋音）。得点加算と同フレームの被弾より前に判定（同時死のときは獲得を優先）。
- ゲームオーバー／リスタート／エクステンドを単体テストで検証。

## 第10段: 敵編隊の隊列飛行（実装済み）

`src/game/enemies.ts` `Squadron`:
- 状態機械（entering→formation→attacking→dispersing）はそのままに、
  **5種の隊形**（vee / line / column / diamond / wedge）をseedで選択。
- リーダー（slot0＝頂点/中心）撃破で残りが離散。
- **編隊全滅ボーナス**: 1機も逃さず全滅させると +1000＋"FORMATION" バナー＋音。
  scene が `recordPlayerKill()` / `fullyCleared()` で判定。
- 隊形選択・全滅判定・line隊形の整列を単体テストで検証。

## 第11段: タイトル/アトラクト画面（実装済み）

`scene.ts`:
- 状態を `title → playing → gameover` に拡張。起動時はタイトル画面。
- タイトル: 星空背景＋"BOSCONIAN"（2倍拡大フォント）＋サブタイトル＋
  "HIGH SCORE nnnnn" ＋点滅 "PRESS FIRE TO START"。ファイアで `resetGame()` 開始。
- ハイスコアはゲームオーバー時に更新（初期値20000）。
- フォント描画に拡大（scale）対応を追加。
- タイトル開始・ハイスコア記録を単体テストで検証。

## 第12段: 手触り・演出の拡充（実装済み）

- **自機の慣性移動**: 速度ベクトル＋加減速。入力方向へ加速、離すと慣性で減速。
  星空スクロールも実速度連動。
- **基地の砲台個別破壊の視覚化**: 砲台撃破位置に暗いクレータ＋点滅する残り火を
  オーバレイ。撃破するほど基地が崩れて見える。
- **敵編隊の発砲**: attacking状態の敵がワールド座標系の弾を自機へ発射（基地弾と
  同じパイプライン）。発射レートはアラート条件でスケール。
- **アトラクトのデモプレイ**: `stepGameplay()` を抽出し、タイトル画面では
  デモAI（最寄り基地へ接近し射撃）で本編を裏で実行。不死。ファイアで即本編開始。
  レーダー帯へのスプライト染み出しバグも修正（右帯を毎フレームクリア）。
