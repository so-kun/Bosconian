# ボスコニアン逆アセンブル解析ノート

このディレクトリには、ROMの逆アセンブルから得た**派生的な理解（解析メモ）**のみを置く。
生の全逆アセンブルリストは著作物であるプログラムのほぼ逐語的な写しになるため、
`analysis/`（gitignore済み）にローカル保持し、**コミットしない**。ここに残すのは
「どのルーチンが何をするか」「アルゴリズムの構造」「再実装の根拠」といった、
オリジナルの記述に還元した知見だけ。

## 解析対象

`bosco3`（version 3）セット。プログラムROMは3つのZ80に分かれる:

| CPU | 領域 | サイズ | 役割（推定・galaga系の類推 + 解析で確定していく） |
|---|---|---|---|
| CPU1 | maincpu | 16KB | メイン。V-blank(RST 38h)駆動のタスクディスパッチャ、ゲーム進行、当たり判定 |
| CPU2 | sub | 8KB | サブ。敵挙動・編隊・弾など（共有RAM経由でCPU1と協調） |
| CPU3 | sub2 | 4KB | サブ2。NMI(ライン64/192)駆動。サウンド指示・補助演算 |

3CPUは `0x7800-0x7fff` の共有RAMと 06XX/5xXX カスタムチップ経由で通信する
（メモリマップは `docs/hardware.md`）。

## 逆アセンブル手法

`tools/disasm/`（オリジナル実装、コミット対象）:
- `z80dasm.ts` — 全命令＋非公式命令対応のZ80逆アセンブラ。制御フロー種別
  （jump/call/ret/rst/cjump…）と分岐先アドレスを返す
- `cli.ts` — ローカルROMを読み、**リセット/RST/NMIベクタを起点とする再帰下降
  トラバース**でコードとデータを分離。`analysis/*.asm`（gitignore）へ出力

再帰下降で「実行され得る」命令だけを辿るので、グラフィック/レベルテーブル等の
データ領域を誤ってコード扱いしない。ジャンプテーブル経由でしか到達しない
コードは初回パスで漏れるため、判明したテーブルを起点シードに追加して繰り返す。

## 到達カバレッジ（初回パス）

`tools/disasm/cli.ts` 実行結果（`analysis/coverage.md`）:

| CPU | 到達命令数 | 直接コード率 | 分岐ターゲット数 |
|---|---|---|---|
| CPU1 (maincpu) | 3,057 | 35.8% | 309 |
| CPU2 (sub) | 2,402 | 51.7% | 244 |
| CPU3 (sub2) | 717 | 32.3% | 71 |

残りはデータ（スプライト配置・敵パラメータ・面構成・文字列など）か、
ジャンプテーブル経由コード。次段でテーブルを特定してシードに追加する。

逆アセンブラ自体は既知エンコーディング10件の単体テストで検証済み
（`tests/disasm.test.ts`）。

## 解析ターゲット（優先順位）

再実装（`src/game/`）に必要な順:

1. **タスクディスパッチャ**（CPU1, RST 38h起点）— 60Hzで回る処理の全体構造。
   Galagaの `task_man.s`（32エントリV-blankディスパッチャ）が構造の手本
2. **起動時セルフテスト**（RAM/ROMチェック → "RAM OK"/"ROM OK"）— 要件2。
   どのルーチンが共有RAMのどのフラグを立てるか
3. **敵編隊・出撃ロジック**（基地からの編隊、リーダー撃破で離散）— 本作の肝
4. **コンディション遷移**（GREEN/YELLOW/RED アラート）と、それに伴う敵の攻撃性変化
5. **スコアリング**（基地コア/砲台/敵/機雷の点数、エクステンド）
6. **機雷・基地の配置と構造**
7. **サウンド指示**（WSGレジスタ列 0x6800-0x681f への書き込みパターン、
   52XX音声トリガ、54XXノイズトリガ）→ フェーズ4のオーディオ実装の根拠

各項目は判明し次第このディレクトリに `NN-name.md` として、
「入力→処理→出力（メモリ番地・フラグ）」の形で記録する。

## 検証戦略

再実装コードは、**自作エミュレータで実ROMを走らせたトレース**（`src/machine`）と
突き合わせて検証する。同一入力列に対しフレーム単位で状態一致を確認できるので、
「解析が正しいか」を常に実測で裏取りできる（`tools/trace-compare/`、フェーズ6）。
