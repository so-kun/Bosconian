# 起動シーケンスのブリングアップ（観測結果）

実ROM（`bosco3`）を自作エミュレータで走らせて観測した、電源投入直後の挙動の記録。
静的解析ではなく**実測**なので信頼性が高い。ここに残すのは挙動の要約（アドレス・
統計）のみで、プログラム本体（逆アセンブル）は含めない。

## 観測手順

`src/machine/bosco.ts` に実ROMをロードして `runFrame()` を回し、`onTrace`（PC）と
`onIoAccess`（I/Oアクセス）フックで挙動を計測（すべてローカル、gitignore）。

## 現時点の到達点

1. **CPU1は起動して実行を継続する**（クラッシュ・暴走なし）。実行ページは
   0x0000 → 0x0100 → 0x3600-0x3800。
2. **メモリテスト段階に到達**。videoram（0x8000-0x8fff）へインクリメント
   パターン（0x01,0x02,…）を書き込み、読み戻している。RAMの読み書き整合性は
   完全（write→read不一致0件 = エミュレータのメモリは正しい）。
3. **その後、タイトなウェイトループ（0x378e-0x37a1、約20バイト）で停止**。
   - このループはvideoramの末尾20バイト（0x87ec-0x87ff）を繰り返し読む。
   - ウォッチドッグ（0x6830）は叩き続ける（＝リセットは食らわない）。
   - **一度もIRQを有効化せず、サブCPUを解放せず、ビデオラッチも触らない。**
     すなわち機械の初期設定に到達する前で止まっている。
4. サブCPUを電源投入時から強制解放しても、CPU1は同じループで停止
   （＝この停止はサブCPUの参加待ちではない）。

## 解決: 「ハング」ではなく「遅い」だった

追加観測で判明: 停止に見えたのは**メモリテストが長く、表示到達まで約815フレーム
（≈13.5秒）かかっていた**ため。フレーム数を伸ばすと正常に進行することを確認:

- frame 815 付近で **misclatch Q3=1 を書いてサブCPUを解放**、続いて frame 819 で
  **IRQを有効化**。videoramのテストパターン（250種のタイル）が消え、
  **25種の実タイル＝テキスト**に置き換わる。
- その画面をレンダリングすると、実機の**電源投入セルフテスト／設定画面**が正しく表示:
  RAM OK / ROM OK / UPRIGHT / 1 COIN 1 CREDIT / 3 SHIPS / RANK A / SOUND 00 /
  ボーナス設定（15000 / 50000 / EVERY 50000 PTS）。
  → **要件2（起動時表示の再現）を達成。**

つまりエミュレータ（Z80×3＋メモリマップ＋タイミング）と、gfx/パレット/タイルマップ
描画は、実ROMを正しく実行・表示できている。0x3780 の「トラップ」に見えた spin は
テスト進行中の中間状態だった。

## 残課題（次段）

- **起動所要フレーム（≈815f）が実機/MAME比で妥当か要検証。** タイミングは名目上正確
  （3.072MHz、60.6fps）だが、実機のRAM OK到達がこれより早いなら、遅延ループの
  反復回数に差を生む要因（未実装のカスタムチップ応答等）がある可能性。MAMEの
  到達フレームと突き合わせる。ブラウザUX的には「高速起動」オプションも検討。
- **設定画面からアトラクトモードへ遷移するか。** 現状は設定画面で滞留（4000f時点）。
  アトラクト進行に 51XX（入力/コイン）や 50XX の応答が要るなら、フェーズ3で対応。
- カスタムチップ（50/51/52/54/06XX）実装で上記2点を解消し、アトラクト〜実プレイへ。

## 確定した基盤（この段階で検証済み）

- Z80コア: zexdoc/zexall 全134グループ合格
- グラフィックデコード: gfx1（キャラ）を全256タイル展開し、フォントが完全に
  読める形で表示されることを確認（`analysis/fontsheet_chars.png`、ローカルのみ）
  → 数字・英字・NAMCOロゴ・記号がすべて正しくデコードされている
- パレット: カラーPROM＋抵抗ネットワーク→RGB、ルックアップPROM→ペンテーブル
- 描画: BG/FGタイルマップ合成、PNG出力（`tools/png.ts`）
